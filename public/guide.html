Guide

What the lab proves

A coding agent never reads your config files directly — its harness merges every applicable layer into one effective context per target file. This lab replays that merge so you can watch precedence resolve.

Teaching model. The fixtures in examples/ are realistic but invented. The merge rules here (specific-over-broad, deny-wins, additive hooks) mirror common agent tooling; your harness may order layers differently — check its docs.

The fixtures

Six config sources, three target files

global

user-global

Personal defaults for every repo: indent: 2, single quotes, conventional commits — plus a deny on read .env* and a hook that redacts secrets from output.

project

project-shared

The committed AGENTS.md + shared settings: Node 20 ESM, Vitest, indent: 4 — it overrides the global indent. Adds a deny on git push --force*.

local

dev-local

A gitignored settings.local.json: this developer prefers double quotes. It beats project and global — but loses to a path-scoped rule.

path

rules-api / rules-ui

Directory-scoped conventions. The api rule switches testRunner to node:test and tries to allow read .env* — the global deny still wins. The ui rule tightens maxFunctionLines and forces single quotes, beating even the developer's local preference.

invoked

skill-pr-review

A review skill loaded only when invoked. Until you check it, it contributes nothing — zero tokens, zero instructions.

Merge rules

How the layers resolve

KindRuleExample in the lab
Instruction blocksAdditive, ordered broad → specificGlobal advice first; rules-api instructions last for src/api/users.ts
Keyed settingsMost specific scope wins; overridden values stay visibletestRunner: project says vitest, api rule says node:test — api wins only under src/api/**
Permissionsdeny > ask > allow across all layersread .env* allowed by the api rule, denied globally → denied
HooksAdditive; deduped by id; a narrower layer can refine but never removeEvery applicable layer's hooks are active on every matching file
Invoked layersContribute only when namedThe pr-review skill's instructions and git diff grant appear only when invoked

Run locally

Inspect the evidence

npm test        # glob + merge + permissions + hooks + examples sync + server
npm run scan    # CLI: effective context for all three targets, bare vs layered
npm run check   # both
npm start       # serve the lab on :3000

Try it: disable project-shared in the lab and watch indent fall back to the global 2 while testRunner still resolves node:test under src/api/**.

Limits

What this demo does not claim

  • The merge order is a teaching model. Claude Code, Cursor, and AGENTS.md-style harnesses each order and combine layers differently — some load nested instruction files additively rather than overriding. Read your tool's docs.
  • Permission rules are matched as literal strings; real harnesses match tool names plus path/command patterns.
  • No model is queried and nothing executes — this shows what context would be assembled, not what a model does with it.
  • Fixtures are invented for instruction, not copied from a real repo's config.
